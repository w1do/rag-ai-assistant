# Развертывание (Deployment)

## Docker Конфигурация
Проект использует многоэтапную (multi-stage) сборку Docker для создания оптимизированного образа для продакшена.

### Этапы сборки
1. **composer_stage**: Установка PHP зависимостей через Composer. Используется образ `php:8.5-fpm-alpine`.
2. **node_stage**: Сборка фронтенд-активов (Vite/React). Используется образ `node:22-alpine`.
3. **Final Stage**: Финальный образ на базе `php:8.5-fpm-alpine` с установленным Nginx и Supervisor для управления процессами.

### Решение проблем с PHP 8.5
В PHP 8.5 произошли изменения в составе расширений и процессе сборки:
1. **Opcache**: Теперь является встроенным расширением и не требует отдельной установки через `docker-php-ext-install`. Попытка установки приводит к ошибке `cp: can't stat 'modules/*': No such file or directory`.
2. **Зависимости GD**: Для корректной сборки расширения `gd` с поддержкой шрифтов и изображений добавлены библиотеки `freetype` и `libjpeg-turbo`, а также произведена предварительная конфигурация через `docker-php-ext-configure`.

## Исправление ошибок сборки
При деплое была обнаружена ошибка `package-lock.json: not found`.

### Причина
Файлы `package-lock.json`, `composer.lock` и директория `docker` были ошибочно добавлены в `.dockerignore`. Это исключало их из контекста сборки, что делало невозможным выполнение команд `COPY` и `npm ci` внутри Docker-контейнера.

### Решение
Данные файлы и директории были удалены из `.dockerignore`. Теперь они доступны в контексте сборки Docker, что гарантирует:
- Использование точных версий зависимостей (через lock-файлы).
- Корректное копирование конфигураций Nginx, PHP и Supervisor из папки `docker/`.

Дополнительно в `Dockerfile` были сделаны следующие исправления:
1. К команде `composer install` был добавлен флаг `--ignore-platform-reqs`. Это необходимо, так как некоторые зависимости (например, `phpword`) требуют расширения PHP (например, `ext-gd`), которые устанавливаются только в финальном образе, но отсутствуют в базовом образе на этапе сборки зависимостей.
2. На этапе `node_stage` добавлено копирование директории `vendor` из `composer_stage`. Это критично для корректной работы SSR (Server Side Rendering), так как файл `resources/js/ssr.tsx` импортирует Ziggy напрямую из директории `vendor`. Без этого `npm run build` завершался с ошибкой `Could not resolve "../../vendor/tightenco/ziggy"`.

## Запуск в продакшене
Образ запускается с использованием `entrypoint.sh`, который настраивает окружение и запускает Supervisor.
Скрипт `entrypoint.sh` автоматически выполняет следующие действия:
1. **Миграции**: Выполняется `php artisan migrate --force` для обновления структуры базы данных.
2. **Кэширование**: Кэшируются конфигурация, маршруты, представления и события для повышения производительности.
3. **Storage Link**: Создается символическая ссылка для хранилища.

Supervisor управляет процессами:
- PHP-FPM
- Nginx
- Laravel Worker (при необходимости)
