# Тарифные планы и ограничения

В системе реализована гибкая система тарифных планов с лимитами на ресурсы и функционал. Основной фокус сделан на тарифе "Старт" и механизмах контроля баланса.

## Тарифный план "Старт" (Базовый)

Этот тариф устанавливается всем пользователям автоматически при регистрации.

### Основные ограничения

| Ресурс | Лимит для "Старт" | Поведение системы |
| --- | --- | --- |
| **Ассистенты** | 1 | Кнопка создания скрыта при достижении лимита. API возвращает `403 Forbidden`. |
| **Ссылки (URL)** | 3 | Форма добавления заблокирована. Лимит проверяется в `AssistantPolicy`. |
| **Голосовые сообщения** | 1 | Кнопка загрузки заблокирована после первого файла. |
| **Документы (PDF/Docx)** | 0 | Полная блокировка вкладки и загрузки. |
| **API Интеграция** | Выключено | Вкладка заблокирована с пометкой "Доступно в PRO". |

## Система контроля баланса

Помимо лимитов по количеству, действия пользователя зависят от состояния его лицевого счета.

- **Блокировка при нуле**: Если баланс пользователя равен 0, он не может добавлять новые знания (ссылки, аудио) или создавать ассистентов, даже если лимиты тарифа еще не исчерпаны.
- **Визуальное уведомление**: При нулевом балансе в верхней части экрана отображается глобальный алерт с предупреждением и кнопкой пополнения.
- **Проверки "на дурака"**: Все ограничения дублируются в `App\Policies\AssistantPolicy`, что исключает обход через прямые запросы к API или консоль.

## Визуализация ограничений

Для улучшения пользовательского опыта (UX) и повышения конверсии в платные тарифы внедрена система наглядных уведомлений:

- **Компонент `LimitReachedCard`**: Специально разработанная карточка в стиле BotSync (закругления 24px, фон `--background-one`, акцентная кнопка `style-1`).
- **Интерактивность**: При наведении на карточку появляется градиентный бордер и анимируется иконка молнии.
- **Применение**:
    - В списке ассистентов: появляется при достижении лимита по количеству.
    - В управлении знаниями: заменяет формы добавления ссылок и аудио при исчерпании лимитов.
    - В разделах PRO: блокирует доступ к документам и API для пользователей тарифа "Старт".

## Механизм смены тарифа

Реализована надежная логика перехода между тарифными планами:

1.  **Списание средств**: При выборе нового тарифа сумма списывается с баланса пользователя.
2.  **Очистка подписок**: Система автоматически отменяет **все** предыдущие активные подписки пользователя перед активацией новой. Это предотвращает проблему "наслаивания" тарифов.
3.  **Приоритет**: При наличии нескольких записей (например, из-за исторических данных) система всегда выбирает последнюю активную подписку (`latest()`).

## Техническая реализация

- **Домен Billing**: Логика смены тарифа находится в `App\Domain\Billing\Handlers\SubscribeHandler`.
- **Авторизация**: Методы `addUrl`, `uploadAudio`, `uploadDocument` и `create` в `AssistantPolicy` проверяют `billing_plans.limits`.
- **Middleware**: `HandleInertiaRequests` передает актуальное состояние подписки и баланса на фронтенд.

## Тестирование
