# Прокси-парсинг через Firecrawl

## Обзор
Для обхода ограничений и обеспечения стабильного парсинга сайтов через Firecrawl внедрена поддержка прокси и система повторных попыток (retries).

## Реализация
- **Сервис**: `App\Domain\Shared\AI\Services\WebParser`
- **Метод**: `parseUrl(string $url)`

### Особенности
1. **Случайный выбор прокси**: Прокси загружаются из файла `proxy.txt` в корне проекта. Для каждого нового запроса (в том числе при повторных попытках) выбирается случайная строка из этого файла. Поддерживаются комментарии (строки, начинающиеся с `#`) и пустые строки — они автоматически игнорируются.
2. **Система повторных попыток**: При возникновении ошибки подключения или если Firecrawl возвращает неуспешный статус (`success: false`), система делает до 3 попыток. Каждая попытка может использовать новый случайный прокси.
3. **Логирование**: Промежуточные неудачные попытки логируются как `warning`, а финальная неудача — как `error`, с указанием использованного прокси и причины ошибки.
4. **Таймауты**: Установлены увеличенные таймауты (60 секунд на чтение, 15 секунд на подключение) для надежной обработки медленных сайтов и прокси.

## Настройка
Добавьте прокси-серверы в файл `proxy.txt` в корне проекта по одному на строку. Поддерживаются форматы HTTP, HTTPS, SOCKS4, SOCKS5.

### Примеры форматов:
- **HTTP**: `http://user:password@host:port`
- **SOCKS5**: `socks5://user:password@host:port`
- **SOCKS5 (DNS через прокси)**: `socks5h://user:password@host:port`

Если файл отсутствует или пуст, парсинг будет осуществляться без прокси.
