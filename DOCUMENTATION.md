# Техническая документация BotSync RAG System

## Архитектура: DDD + CQRS

Проект реализован с использованием подходов Domain-Driven Design (DDD) и Command Query Responsibility Segregation (CQRS).

### Структура каталогов
Вся бизнес-логика вынесена в директорию `app/Domain`, разделенную на домены:

- **Assistant**: Управление ассистентами, документами и чанками.
- **Chat**: История переписки и логика взаимодействия с ассистентом. Включает генерацию саммари последних диалогов (`GetAssistantChatSummaryQuery`).
- **Knowledge**: Логика управления базой знаний и генерации контента на основе внешних источников.
- **Billing**: Управление балансом, тарифными планами и историей платежей.
- **Shared**: Общие сервисы, такие как RAG-пайплайн.

### Слои (CQRS)
Внутри каждого домена выделены следующие слои:

- **Models**: Eloquent-модели, специфичные для домена.
- **Actions (Commands)**: Классы, выполняющие операции записи (создание, обновление, удаление, запуск процессов).
- **Queries**: Классы, выполняющие только чтение данных для отображения в UI.
- **Jobs**: Фоновые задачи домена.

Пример использования в контроллере:
```php
public function store(Request $request, StoreAssistantAction $action): RedirectResponse
{
    // Валидация в контроллере
    $validated = $request->validate([...]);
    
    // Выполнение бизнес-логики через Action
    $action->execute(auth()->user(), $validated);

    return redirect()->route('assistants.index');
}
```

## AI Интеграция и RAG

### LLPhant
Основной фреймворк для реализации RAG (Retrieval-Augmented Generation). Используется для:
- Чтения документов (PDF, Docx, TXT).
- Генерации эмбеддингов.
- Поиска сходства в векторной БД Qdrant.
- Генерации ответов (QA).

### Векторная БД: Qdrant
Используется для хранения векторов текста. Для каждого ассистента создается отдельная коллекция `assistant_{id}` с размерностью 1536 (OpenAI embeddings).

### Интеграция с PolzaAi
Система поддерживает работу с PolzaAi (и другими OpenAI-совместимыми провайдерами).
Настройка производится в `.env` через переменные:
- `OPENAI_API_KEY`: Ваш API ключ.
- `OPENAI_BASE_URL`: Базовый URL провайдера (например, `https://api.polzai.ru/v1`).

### Фоновые процессы
Длительные операции вынесены в очереди (управляются через Supervisor и Laravel Horizon):
1. **ProcessKnowledgeJob**: Чтение файла, извлечение текста (расшифровка), чанкинг, генерация эмбеддингов и сохранение в Qdrant.
2. **TranscribeVoiceJob**: Транскрипция аудио через Whisper и последующая индексация.
3. **GenerateKnowledgeJob**: Парсинг текста с URL и генерация записи в базу знаний через LLM.
4. **API Callback**: Прямая индексация подготовленных данных (вопросы и ответы) через REST API.

Для обеспечения надежности в Supervisor настроен стандартный воркер `queue:work`, а для расширенного мониторинга используется Laravel Horizon (доступен по адресу `/horizon`). Доступ в продакшене регулируется через `HORIZON_EMAILS` в `.env`.

## Переменные окружения (.env)
Все чувствительные данные вынесены в `.env`:
- `QDRANT_HOST`, `QDRANT_PORT`: Настройки подключения к векторному хранилищу.
- `OPENAI_API_KEY`, `OPENAI_BASE_URL`: Настройки AI-провайдера.
- `QDRANT_COLLECTION`: Название основной коллекции (опционально).

## Инфраструктура и Проксирование

### Настройка Nginx

Система использует стандартную конфигурацию Nginx для Laravel приложений.

**Принцип работы:**
- **Laravel**: Nginx направляет все запросы в `public/index.php` Laravel. Это позволяет обрабатывать любые маршруты, определенные в `routes/web.php` или `routes/api.php`.
- **Статика**: Статические файлы (Vite ассеты в `/build/`, файлы в `public/`) отдаются напрямую Nginx.

**Конфигурация:**
- Конфигурация Nginx находится в `docker/nginx.conf`.
- Используется PHP-FPM для обработки PHP-запросов.

## Развертывание (Docker)

Проект включает оптимизированную многостадийную конфигурацию Docker для продакшена.

### Особенности сборки
- **Multi-stage build**: Раздельные стадии для установки PHP-зависимостей, сборки фронтенда и финального рантайма.
- **Минимальный размер**: Использование образов на базе Alpine Linux.
- **Производительность**: Настроенный Opcache, кэширование конфигураций Laravel при старте, Nginx для отдачи статики.
- **Универсальность**: PHP-FPM и Nginx управляются через Supervisor внутри одного контейнера (для простоты развертывания).

### Сборка и запуск
```bash
# Сборка образа (с инвалидацией кеша фронтенда для получения свежих ассетов)
docker build --build-arg CACHEBUST=$(date +%s) -t rag-system-prod .

# Запуск контейнера
docker run -d -p 8080:80 --env-file .env rag-system-prod
```

> **Важно**: флаг `--build-arg CACHEBUST=$(date +%s)` гарантирует, что `npm run build` всегда выполняется заново со свежими исходниками, даже если `package.json` не изменился. Без него Docker может использовать закешированный слой со старыми ассетами.

### Структура Docker-папки
- `Dockerfile`: Инструкции по сборке.
- `docker/nginx.conf`: Оптимизированный конфиг Nginx.
- `docker/php.ini`: Настройки PHP (Opcache, лимиты памяти).
- `docker/supervisord.conf`: Конфигурация Supervisor.
- `docker/entrypoint.sh`: Скрипт инициализации (кеширование Laravel).
