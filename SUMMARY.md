# Summary

## Текущее состояние
Проект представляет собой RAG-систему на базе Laravel 13.
Внедрена стабильная система парсинга веб-страниц через Firecrawl с поддержкой прокси и механизмом повторных попыток.

## Ключевые изменения
- Разработан современный лендинг проекта в `Welcome.tsx` с Hero-секцией, интерактивным демо-чатом, блоком преимуществ и тарифными планами.
- Реализован функционал демонстрационного чата с подсказками-хинтами для вовлечения пользователей.
- Интегрирована секция тарифов, стилистически согласованная с остальным интерфейсом системы.
- Добавлена документация по лендингу в `docs/landing_page.md`.
- Реализована секция "Технологии и нейросети" с использованием Swiper для демонстрации стека (Claude, GPT, Gemini, Qdrant и др.).
- Реализована интерактивная секция FAQ с 10 развернутыми ответами, охватывающими ключевые функции: RAG, мониторинг, боты для MAX и голосовое обучение.
- Создана секция "Процесс настройки" (Setup Process) с пошаговой визуализацией этапов от регистрации до встройки бота.
- Создана секция "Кто использует умных ботов" с карточками отраслей (ретейл, e-commerce, автосервисы, агентства и др.) для улучшения SEO и демонстрации кейсов.
- Реализована секция "Интеграция и синхронизация данных" (DataSync) на лендинге, описывающая возможности подключения к CRM, закрытым системам и автопулингу данных.
- Добавлена подробная документация по интеграции в `docs/data_sync.md`.
- Исправлена критическая ошибка "Element type is invalid", вызывавшая белый экран на страницах чата и маркетплейса.
- Оптимизированы импорты `react-markdown` и `lucide-react` для полной совместимости с React 19 и Vite 6.
- Внедрен надежный метод импорта иконок через пространство имен (`import * as Lucide`) и использование `useMemo` для повышения стабильности страниц.
- Исправлено поведение скролла в демо-чате на лендинге: теперь прокручивается только окно чата, а не вся страница.
- Реализована кастомизация ассистента: добавлены поля `style`, `brand_name`, `phone`, `social` and `fallback`.
- Добавлена документация по настройкам ассистента в `docs/assistant_settings.md`.
- Проведена SEO-оптимизация лендинга `Welcome.tsx`: обновлены мета-теги, заголовки и текстовые блоки с использованием ключевых слов ("ии онлайн", "чат ии", "rag системы" и др.).
- Проект переименован из "AI Boost" в "BotSync": обновлены заголовки, мета-теги, тексты на лендинге, в маркетплейсе и во всей технической документации.
- Создан Маркетплейс чатов (`/chats`): полноценный каталог ИИ-ассистентов с фильтрацией по категориям (ИИ чаты, Общение, Бизнес, RAG) и поиском в реальном времени.
- Внедрен `MarketplaceController` для управления отображением доступных чатов, реализована логика автоматического распределения по категориям и фильтрация по статусам (`active`, `ready`).
- Добавлена документация по маркетплейсу в `docs/marketplace.md`.
- Внедрены предопределенные стили общения: коммерческий, деловой, грубый и позитивный.
- Обновлена логика формирования системного промпта в `AskAssistantQuery` для учета индивидуальных настроек ассистента.
- Реализована логика `fallback`: теперь ассистент использует заданное сообщение, если не может найти ответ в контексте.
- Исправлена критическая ошибка `Class "Qdrant\Models\Request\Points\BatchIdSelector" not found`, возникавшая при удалении сайтов или знаний.
- Повышена надежность индексации данных в Qdrant путем добавления механизма повторных попыток (retries) при сбоях сети.
- Исправлена логика обновления статусов: теперь статус "готово" устанавливается только после успешного завершения индексации в векторном хранилище.
- Исправлены критические ошибки в `VectorStoreManager`, связанные с использованием неверных имен классов клиента Qdrant.
- Реализована автоматическая очистка старых чанков в локальной БД при переиндексации данных, что предотвращает дублирование.
- Исправлена проблема, из-за которой `qdrant_id` не сохранялся в локальной базе данных, что создавало видимость отсутствия данных в Qdrant.
- Добавлена генерация детерминированных UUID для чанков на основе их типа источника, имени и номера чанка.
- Улучшено логирование процесса индексации: теперь логируется количество созданных чанков и длина полученного контента.
- Исправлена ошибка `Unknown named parameter $knowledgeId` при добавлении сайта, загрузке документов и аудио.
- Исправлена проблема с некорректными метаданными документов (пустой `hash` и `sourceType: "manual"`) при парсинге сайтов и транскрибации аудио.
- Вызовы `IndexAssistantDocumentsAction->execute` переведены на использование позиционных аргументов вместо именованных.
- Обновлен `WebParser` для работы с ротацией прокси.
- Добавлена логика `retries` (3 попытки) для HTTP-запросов.
- Интегрировано подробное логирование ошибок парсинга.
- Реализованы тесты для проверки отказоустойчивости парсера.
- Добавлена PHPDoc документация для ключевых классов действий (Actions).
- Создана оптимизированная Docker-конфигурация для продакшена (Multi-stage, Alpine, PHP 8.5, Nginx + Supervisor).
- Исправлена критическая ошибка сборки Docker: файлы `package-lock.json`, `composer.lock` и директория `docker` удалены из `.dockerignore` для обеспечения корректной работы команд `COPY` и `npm ci`/`composer install`.
- Устранена ошибка установки зависимостей Composer в Docker за счет использования флага `--ignore-platform-reqs`, что позволило обойти отсутствие расширения `ext-gd` на этапе сборки.
- Исправлена ошибка сборки фронтенда `Could not resolve "../../vendor/tightenco/ziggy"` в SSR: в `Dockerfile` на этапе `node_stage` теперь копируется директория `vendor`, необходимая для импорта маршрутов Ziggy.
- Исправлена критическая ошибка `cp: can't stat 'modules/*'` при сборке PHP 8.5: удалена лишняя попытка установки `opcache` (теперь встроен) и добавлены недостающие зависимости для `gd`.
- В скрипт деплоя (`entrypoint.sh`) добавлена команда автоматического запуска миграций `php artisan migrate --force`.

## Vibe Coding
Код следует принципам DDD. Используются современные возможности Laravel (v11/v13) для работы с HTTP-клиентом.
Вектор развития: повышение надежности сбора данных для базы знаний RAG.
